# HelixQA bank id floor — the case ids banks/ is known to contain.
#
# WHY: a truncated or half-written bank file still parses as valid
# YAML and simply declares fewer cases, so nothing else in the loader
# can see the loss (HXC-305 F2: truncating atmosphere.yaml at a case
# boundary silently took the catalog from 3046 to 3006 at exit 0).
# Every id below MUST end up loaded, or reported as an excluded
# cross-bank duplicate; a missing one hard-fails the directory scan
# and is named. See pkg/testbank/loader.go checkBankIDFloor.
#
# This is a FLOOR, not a snapshot: ADDING cases never trips it and
# never needs this file touched. Only REMOVING a case does — which is
# the point, so a removal is reviewed rather than silent.
#
# REGENERATE (after a deliberate removal), header preserved:
#   bin/helixqa banks regen-floor --banks banks
#
# Do NOT regenerate with a shell pipeline over `helixqa list`. That
# was documented here until HXC-305 round 6 measured it: a floor is
# only ever regenerated while this check is FAILING, `list` exits 1
# with no stdout on exactly that state, and the pipeline took `sort`'s
# exit status — so `&& mv` replaced this file's 3046 ids with a
# header-only file at exit 0 and disarmed the check. regen-floor
# reads the catalog with the check disabled by construction, refuses
# to write an empty floor, names every id it stops protecting, and
# writes atomically.
